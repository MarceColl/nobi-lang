# SQLite Everywhere Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Nobi uses SQLite only, with no Postgres, and boots from a fresh checkout.

**Architecture:** `Nobi.Repo` switches to `Ecto.Adapters.SQLite3` with a single file under `.nobi/`. Migrations are rewritten portably and edited in place, since nothing is deployed. `deployments.hosts` becomes a join table. Every query is audited for Postgres-only features.

**Tech Stack:** `ecto_sqlite3`, Ecto, ExUnit with the SQL sandbox.

**Spec:** `docs/superpowers/specs/2026-10-16-sqlite-design.md`

## Global Constraints

- **Dependencies:** `postgrex` is removed and `{:ecto_sqlite3, "~> 0.17"}` added; use the newest release of that line already published. `docker-compose.yml` is deleted.
- **Paths:**
  - dev: `.nobi/nobi.db`
  - test: `.nobi/test#{System.get_env("MIX_TEST_PARTITION")}.db`
  - prod: `Path.join(System.get_env("NOBI_DATA", "/var/lib/nobi"), "nobi.db")`, set in `runtime.exs`
  - `.nobi/` is git-ignored.
  - Parent directories are created before the Repo starts, from config or the application `start/2`.
- **Pragmas:** `journal_mode: :wal`, `busy_timeout: 5000`, foreign keys on.
- **Behaviour and test strength stay the same.** Every existing assertion still holds, concurrency tests included. If a test must become `async: false` for SQLite's single writer, say so in the report.
- `mix precommit` must be green after each task. VCS is jj; never use git commit or git stash.

## Review Focus

1. **Concurrent writers:** two universes staging at once, and ten concurrent `Registry.create` calls. Expected: no `database is locked` errors, because `busy_timeout` and serialization absorb them, and the exact outcomes are unchanged.
2. **Host lookup through the new join table.** Expected: identical `Deployment.resolve` behaviour, case- and port-normalised, using an indexed lookup.
3. **Fresh checkout** (`rm -rf .nobi`). Expected: `mix nobi.start` creates the directory and DB, migrates, and serves.

### Task 1: Adapter, config, portable migrations, query audit

**Files:** `mix.exs`, `mix.lock`, `config/{config,dev,test,runtime}.exs`, `.gitignore`, every migration in `priv/repo/migrations/`, `lib/nobi/{cas,deployment}.ex`, `lib/nobi/universe/registry.ex`, `lib/nobi/elm/store.ex`, `test/support/*_case.ex`, `docker-compose.yml` (delete).

- [ ] **Step 1:** Swap the dependency and config, and edit the migrations in place:
  - `timestamptz` becomes `:utc_datetime_usec`, `bytea` becomes `:binary`;
  - `deployments.hosts` becomes the `deployment_hosts(deployment text, host text, primary key (deployment, host))` table, with an index on `host`;
  - database defaults SQLite can't express move to Elixir.
- [ ] **Step 2:** Update `Nobi.Deployment` for the join table. Insert the hosts in the same transaction as the deployment; resolve with an indexed join. Audit every Repo call in lib/ for arrays, `ANY`, `FOR UPDATE`, `ILIKE` and parameter limits, and make each portable.
- [ ] **Step 3:** Run `mix ecto.drop && mix ecto.create && mix ecto.migrate` for test and dev, then the full suite, and fix what breaks. Run the suite on 3 seeds plus `--include quint --include perf`.
- [ ] **Step 4:** `mix precommit`, then `jj commit -m "feat: SQLite everywhere"`.
