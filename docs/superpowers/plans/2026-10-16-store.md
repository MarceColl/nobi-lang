# Store Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Yabu apps persist data through `Cmd.store.*`, with one SQLite file per deployment, one table per model, protobuf-style add-only model evolution checked at promotion, and a pure-closure `tx`.

**Architecture:**
- **Language:** stored models (`id : Uuid`), field defaults, an evolution rule at promotion, a closure `tx` with `Store.get`/`list`, and `Tx.delete(id)`.
- **Runtime:** `Kinoko.Data`, outside `lib/kinoko/lang`, opens per-deployment files, syncs schemas, and encodes and decodes rows. `Kinoko.Data.Tx` coordinates transactions.
- **Hosting:** DeploymentLive lowers store effects to tasks against the deployment's data.

**Tech Stack:** `ecto_sqlite3` (a dynamic repo per file), the Elm effects runtime, Exec workers.

**Spec:** `docs/superpowers/specs/2026-10-16-store-design.md`

## Global Constraints

- **`Kinoko.Lang` stays pure.**
  - Store reads inside `tx` go through a runtime hook module outside `lib/kinoko/lang`, the same way `always` does.
  - No atoms come from user text. Table and column names are strings.
- **`Kinoko.Data.Repo`** is a separate Repo module with its own config. Pragmas: `journal_mode: :wal`, `busy_timeout: 5000`, `foreign_keys: :on`, `default_transaction_mode: :immediate`. Other rules:
  - It is not in `ecto_repos`, and is never a dynamic instance of `Kinoko.Repo`.
  - Pool size is 2.
  - Files live at `<data dir>/data/<deployment>.db`.
- **Opening a deployment's file is single-flight.** It runs through a unique `Registry` name under a `DynamicSupervisor`, because `ecto_sqlite3`'s migration lock is a no-op. The open creates the meta tables once.
- **`put_dynamic_repo` is process-scoped.** Effect tasks receive the repo pid explicitly.
- **Names:**
  - Table: the symbol lowercased with `.` → `__`, quoted.
  - Fallback: `m_<first 12 hex of sha256(symbol)>`, recorded in `_kinoko_tables(symbol text primary key, tbl text not null)`.
  - Columns: field names, quoted; anything outside `[a-z0-9_]` gets the same hashed fallback, recorded in `_kinoko_columns`.
- **Column types:**
  - `id TEXT PRIMARY KEY` and `_seq INTEGER NOT NULL`;
  - `Int`/`Bool` → `INTEGER`, `String`/`Uuid` → `TEXT`;
  - `Option<scalar>` → nullable scalar;
  - everything else → `TEXT` JSON, through `Rt.Json`.
- **Limits and errors:**
  - `list` is capped at 10,000 rows; above that, `"too-many-rows"`.
  - Error codes keep **busy/locked** (`"unavailable"`) separate from **constraint** and **decode** errors (`"store"`).
- **New checker codes:** `"not-stored"`, `"bad-default"`, `"model-evolution"`.
- **Store tests** never use the Ecto sandbox. Each test gets a temp file and a real pool, and `async: true` is allowed.
- `mix precommit` must be green after every task. VCS is jj (`jj commit -m`); never use git commit or git stash.

## Review Focus

1. **A process killed mid-transaction on a store file.** Expected: another writer gets the lock well within `busy_timeout`. If not, add a `before_disconnect` ROLLBACK. *Task 4.*
2. **20 concurrent `tx` increments on one row.** Expected: the final value is exactly 20, with no lost update. *Task 4.*
3. **A deployment pinned to an older commit reading rows written by newer code** (extra columns, newer fields). Expected: the rows decode and the extra columns are ignored. *Task 5.*
4. **The evolution rule:** retyping a field, removing a field, and adding a field with neither a default nor `Option`. Expected: each is refused with the exact reason, staged, and never promoted. *Task 1.*
5. **The `list` cap, and a corrupt JSON cell.** Expected: a clear error, never a crash and never a wrong value. *Task 3.*

### Task 1: Language: stored models, defaults, evolution rule, `tx` closure types

**Files:** the parser, format, AST and checker under `lib/kinoko/lang/` (types for decl, extract, stdlib), and `universe.ex`/`universe/db.ex` for the promotion rule. Tests: `test/kinoko/lang/store_lang_test.exs`.

**Interfaces:**
- **Field syntax:** `name : Type = <constant>`.
- **Model signature:** `{:model, [{field, type, default | :none}]}`, with defaults stored as typed constant ASTs or values (document which).
- **Stored model:** a model with an `id : Uuid` field. `Cmd.store.*`, `Tx.*` and `Store.*` on anything else gives `"not-stored"`.
- **Types:**

  ```
  Cmd.store.tx(fn (s : Store) -> (List<Tx.Op>, r) end, fn (res : Result<(List<Uuid>, r), String>) -> msg end) : Cmd<msg>
  Store.get(s, id : Uuid) : Option<M>      -- M from the expected type
  Store.list(s) : List<M>                   -- M from the expected type
  Tx.insert(row : M) : Tx.Op
  Tx.update(id : Uuid, row : M) : Tx.Op
  Tx.delete(id : Uuid) : Tx.Op
  ```

  The list form of `tx` is removed. `Store` is a new builtin type.
- **Evolution rule at promotion.** A patch that redefines a committed stored model is compared field by field with the committed signature, through salsa reads, so checking stays incremental. Retyped, removed, and new fields that are neither defaulted nor `Option` are all refused with `"model-evolution"`, and the message names the fix. Default changes are allowed, and the first commit is free.

- [ ] **Failing tests first.** Parse, format and CID with defaults; `"bad-default"` (calls, symbol references, wrong type); `"not-stored"`; each evolution case, through `Kinoko.Universe` staging (Review Focus 4); `tx` closure typing; `Store.get`/`list` typing by expected type; `Tx.delete` by id. The piece-1 oracle stays green: update the oracle signature decoding for the 3-tuple fields and list the changes.
- [ ] **Implement**, then `mix precommit`, then `jj commit -m "feat(lang): stored models, field defaults, evolution rule, tx closure"`.

### Task 2: Codegen and runtime values for store effects

**Files:** `lib/kinoko/lang/codegen*.ex`, `lib/kinoko/lang/rt*.ex`, `lib/kinoko/exec/hooks.ex` (or a new `lib/kinoko/data/hooks.ex`).

**Interfaces:**
- **Store effect values**, flat, documented in Rt:
  - `{:cmd, {:effect, "Cmd.store.insert", model, [row, cb]}}`;
  - likewise for `list` (`[cb]`), `get` (`[id, cb]`), `update` (`[id, row, cb]`) and `delete` (`[id, cb]`);
  - `tx` is `[body_fun, cb]`.
  - `model` is the stored model symbol, recorded at codegen from types.
- **`Tx.Op` values:** `{:tx, :insert, model, row}`, `{:tx, :update, model, id, row}`, `{:tx, :delete, model, id}`.
- **`Store.get`/`Store.list`** compile to calls into the hook module, with `(store_handle, model, …)`. The handle is opaque, `{:store, coordinator_pid, ref}`. Calling it outside a live transaction gives a runtime error, `"store handle used outside its transaction"`.
- **The model table** (`__yabu__(:models)`) now includes defaults.

- [ ] **Tests:** the image compiles with store effects; the effect values have the right shape; the hook is called with the right model; a handle used after its transaction errors.
- [ ] **Implement**, then `mix precommit`, then `jj commit -m "feat(lang): store effect values and Store hooks"`.

### Task 3: `Kinoko.Data` storage

**Files:** `lib/kinoko/data.ex`, `lib/kinoko/data/{repo,opener,schema,codec}.ex`, `application.ex` (Registry and DynamicSupervisor), `config/*.exs` (`Kinoko.Data.Repo` config). Tests: `test/kinoko/data_test.exs` (temp files, async).

**Interfaces:**

```elixir
Kinoko.Data.open(deployment) :: {:ok, repo_pid}                          # single-flight; creates file + meta tables
Kinoko.Data.ensure(repo, model, model_sig) :: :ok                          # create table / ADD COLUMN (DEFAULT for defaulted scalars); cached per sig hash
Kinoko.Data.insert(repo, model, sig, row) :: {:ok, uuid} | {:error, reason}
Kinoko.Data.list(repo, model, sig) :: {:ok, [row]} | {:error, reason}     # _seq order, cap 10_000
Kinoko.Data.get(repo, model, sig, id) :: {:ok, row | nil} | {:error, reason}
Kinoko.Data.update(repo, model, sig, id, row) :: {:ok, uuid} | {:error, reason}   # whole-row replace; missing id → {:error, not_found}
Kinoko.Data.delete(repo, model, sig, id) :: {:ok, row | nil} | {:error, reason}
Kinoko.Data.stats(deployment) :: [%{model, table, rows, columns}]          # console
```

- **Rows** are BEAM values (`{:rec, model, fields}`) in the Rt representation.
- **Encoding** is by column type. **Decoding** is type-directed by `sig`: a missing column, or NULL in a non-Option field, takes the default. An undecodable cell gives `{:error, %{code: "store", …}}`.
- **`insert`** mints a v4 UUID and overwrites the row's `id`.

- [ ] **Failing tests:**
  - open is single-flight under 10 concurrent opens;
  - create and evolve a table, adding columns with defaults;
  - v1 rows read under v2;
  - Option and NULL;
  - compound JSON round-trip;
  - name mapping, including the fallback;
  - one file per deployment;
  - the `list` cap and a corrupt JSON cell (Review Focus 5);
  - extra columns ignored.
- [ ] **Implement**, then `mix precommit`, then `jj commit -m "feat: Kinoko.Data per-deployment SQLite storage"`.

### Task 4: Transactions

**Files:** `lib/kinoko/data/tx.ex` and the hook module from Task 2. Tests: `test/kinoko/data/tx_test.exs`.

**Interfaces:**

```elixir
Kinoko.Data.Tx.run(repo, image_or_target, body_fun, opts) :: {:ok, {inserted_ids, r}} | {:error, message}
```

1. A coordinator process opens `BEGIN IMMEDIATE` on the deployment repo.
2. The body runs in an Exec worker with a store handle; `Store.get`/`list` request reads from the coordinator.
3. The coordinator applies the returned ops in order (inserts mint ids), then commits.
4. **Errors:**
   - any error rolls back;
   - busy is retried up to 3 times;
   - timeouts follow Exec's rules;
   - the error message is user-facing; internals are logged, not shown.

- [ ] **Failing tests:** Review Focus 1 and 2; a body crash rolls back; a timeout rolls back; inserted ids come back in order; a read sees writes from earlier ops of the same transaction (decide and document whether the body sees its own ops; recommended: no, ops apply after the body returns, so the body sees the pre-transaction snapshot); an update of a missing id gives `Err`.
- [ ] **Implement**, then `mix precommit`, then `jj commit -m "feat: closure transactions"`.
