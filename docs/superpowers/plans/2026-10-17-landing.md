# Landing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** a static, language-style homepage in the Vellum look, with real code and a real install transcript, built into `site/dist/` and deployable to GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-10-17-landing-design.md`. It is binding. Section ideas come from `docs/design/nobi-marketing/LANGUAGE-SITES-RESEARCH.md`. Vellum tokens are in `assets/css/app.css`, and Vellum component values are in `docs/design/nobi-vellum/Nobi Vellum.dc.html`.

## Global Constraints

- **Use Vellum values only.** No new palette. Colours come from the `--k-*` tokens; the families are Chivo, IBM Plex Mono and Newsreader. Card, chip, callout and terminal styling are reused from the console and prototype values.
- **Every claim is true of the current build.**
  - Code samples are `.nobi` files that are tested.
  - The transcript comes from a real run.
- **Hands off:**
  - Never publish, push, or enable Pages.
  - Never touch :4000. Previews run on 4124. Kill only your own PID, never `pkill`.
  - Never create or edit README files.
- **Process:**
  - VCS is jj.
  - `mix precommit` must be green.

## Review Focus

1. **Truthfulness.** Each sentence maps to an existing feature. Each sample's verdict is asserted by a test.
2. **Craft.** Typographic hierarchy, spacing rhythm, and a 360px layout. Check against screenshots at 1440 and 390.
3. **Static purity.** No CDN links, no framework, and it works from `file://` or any static host.

### Task 1: Samples and build pipeline

**Files:**
- `site/samples/*.nobi`: a counter or todo app, a stored model with evolution, and the mistake sample.
- `test/site/samples_test.exs`: loads each sample into a fresh universe through `Nobi.Universe` and asserts promoted, or the exact reason code.
- `lib/mix/tasks/site.build.ex` and `site.serve.ex`.
- A `site` Tailwind profile in `config/config.exs`.
- `site/src/index.html.eex` (or HEEx rendered by the task), which includes the samples verbatim.
- `site/src/site.css`, which imports Tailwind and defines the tokens: the same `--k-*` values, with `@font-face` pointing at `fonts/`.

- [ ] Write the failing sample tests first.
- [ ] Make `mix site.build` produce `site/dist/{index.html, site.css, fonts/*, copy.js}`.
- [ ] Commit with `jj commit -m "feat(site): samples and static build"`.

### Task 2: Page content and design

Build the 8 sections in the spec in the Vellum look, with copy drafted from the built features. Mark every sentence of drafted copy in a `site/COPY.md` table for Marce to edit, with these columns: section, sentence, and the feature that backs it.

Use the transcript from `site/samples/session.txt`, captured from the distribution binary. If the binary isn't built yet, use `mix nobi.start` plus the real MCP calls, and note it.

- [ ] Take screenshots at 1440×900 and 390×844 with headless Chrome into the SDD workspace.
- [ ] Check contrast.
- [ ] Commit with `jj commit -m "feat(site): landing page"`.

### Task 3: Pages workflow

**Files:** `.github/workflows/pages.yml`, which runs `mix site.build` and deploys `site/dist` with `actions/deploy-pages`. Trigger it on push to main for paths `site/**`, plus `workflow_dispatch`. It is written but not run.

- [ ] Check it with `actionlint` if available.
- [ ] Commit with `jj commit -m "build(site): GitHub Pages workflow"`.
